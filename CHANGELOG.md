# Changelog

Release-owned: pull requests do not edit this file. Release notes go in the
pull request body, which becomes the squash commit; at release,
`scripts/changelog-draft.sh` lists the merged changes since the last tag.
GitHub Release notes come from the matching version section.

The format is [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.6.0] - 2026-11-27

Same contents as `v0.6.0-rc.1`.

### Upgrade

Tenkai pins the console in `ui/console.pin`. To serve this release, pin `v0.6.0` with the SHA-256 of `tenkai-console-v0.6.0.zip` from `SHA256SUMS`. Rollback is pinning the previous zip.

The bundle requires `/healthz` to list contract `tenkai.http.v1`. Types are generated from a Tenkai `main` commit ahead of Tenkai `v0.9.1`. Against a 0.9.1 server, screens for later routes (debug sessions, recalled-upgrade, and other post-0.9.1 APIs) read as unavailable. Same-origin and air-gapped operation are unchanged.

`/` is the Environments table. Home is gone. Search is an overlay (⌘K). Catalog publish, promote, and recall live on the product. Register environments with `tenkaictl`.

### Added

- **Object pages**, places rail, corner Actions, two-column overviews, and this page's Actions in the search palette (#209, #219, #220, #221, #222, #226, #227, #228, #229, #231, #232, #233, #234).
- **Limited recall** as one environment table, with range exclusions and an optional instance count (#225).
- **Debug sessions** on an instance (#224).
- **Canary designations** by selector (#218).
- **Config presets** and override conflicts (#217).
- **Delivery metrics** on an environment (#216).
- **Stop and start** an instance (#215).
- **Unmanaged workloads** and adopt matching pins (#214).
- **Upgrade onto an advisory-recalled release** with lower exposure (#213).
- **Artifact availability** on plans and approvals (#212).
- **Label actor, time, and history** (#210).

### Changed

- Signed-in default is Environments. Attention is a count on that place. Releases is the product table; catalog tools moved onto the product, release, environment, or Exposure.

## [0.4.0] - 2026-11-15

The console for Tenkai 0.9. Same contents as `v0.4.0-rc.1`.

### Upgrade

Tenkai pins the console in `ui/console.pin`. To serve this release, pin `v0.4.0` with the SHA-256 of `tenkai-console-v0.4.0.zip` from `SHA256SUMS`. Rollback is pinning the previous zip.

The bundle still requires `/healthz` to list contract `tenkai.http.v1`. Types are generated from the signed Tenkai `v0.9.0` schema. Against a 0.8 server, the screens for 0.9 routes read as unavailable, a bare-array delivery list reads as the whole list, and a hold by selector reads as refused. Same-origin and air-gapped operation are unchanged.

### Added

- **Instance health** with checks, observed time, and repairing checks (#155, #172).
- **Channel promotion policy** status, soak detail, and pause/resume (#157, #171).
- **What blocks an instance's next change** (#159).
- **Automatic environment holds** and the failure threshold (#160), and **hold by selector** with a live match preview (#185).
- **Cancel a running apply**, with the cancel outcome, skipped steps, and rollback hold (#162, #174).
- **Sealed secret age** and rotation due (#165).
- **Advisory waivers** on exposure findings, the waiver list, and grace periods (#166, #180).
- **Environment and release labels**, view and edit (#170).
- **Owners and notification endpoints**, with owner reachability and single product endpoint removal (#169, #182).
- **Rendered target changes** and the **approval brief** on plans and approvals (#173, #175).
- **Health recall rule**: recall details, measured shares, removal progress, and editing the rule (#176, #189).
- **Upgrade pace** for a channel from Releases, pacing progress with early admit, and the configured pace next to the pace in effect (#178, #179, #184).
- **Attributed delivery failures** and the fleet route flag (#187).

### Changed

- Webhook delivery lists are paged (#191).
- The Tenkai contract is pinned to the `v0.9.0` release (#195). `pnpm api:sync` also accepts a full commit on Tenkai `main` (#154).

## [0.3.0] - 2026-11-11

### Upgrade

Tenkai pins the console in `ui/console.pin`. To serve this release, pin `v0.3.0` with the SHA-256 of `tenkai-console-v0.3.0.zip` from `SHA256SUMS`. Rollback is pinning the previous zip.

The bundle still requires `/healthz` to list contract `tenkai.http.v1`. Types are generated from the signed Tenkai `v0.6.0` schema. Newer inspect and status fields (instances, drift, history, issuer, identity, grants, apply steps) are parsed at runtime; a server that omits them shows unavailable or none. A tagged Tenkai 0.8.0 is not required.

### Added

- **Host account sign-in** over an SSH forward, with the groups that granted access (#109).
- **Organisation SSO** on the sign-in screen, with a token fallback (#68, #62).
- **First administrator** banner and grant form (#88).
- **Instances and bindings** on the environment, including health and a read-only binding matrix (#140).
- **Peer grants** from bindings, labeled granted (#147).
- **Workload identity** per instance: expiry and renewal state, report-only (#146).
- **Environment identity issuer** and rotation, with waiting instances by name (#145).
- **Deployment attempt history** with filter, paging, and structured failure cause (#141, #144).
- **Live-spec drift** on the environment, report-only (#143).
- **Overlay schema checks** on plans and environments; secrets as names only (#142).
- **Product dependencies** and **dependency holds** with resume state (#110, #139).
- **Compatibility profile v2** on the release panel (#129).
- **Per-step apply results**, including restored, cut, and not-run steps (#148).
- **Exposure** screen and recall follow-through (#90).
- **Runners** enroll, list, and revoke (#71).
- **Server** tab: transport, runner identity, mTLS, CA fingerprint (#72, #73).
- **Trust** tab: signing trust, revocation list, TLS certificates (#74, #75).
- **Imports** tab: jobs, per-entry progress, archive digest match, content inventory (#81, #85, #87).
- **Operations** tab: backups, exports, export history, restore drills, ranged audit exports (#79, #84, #86).
- Create and edit environments: facts, constraints, maintenance windows, webhooks, approval policy (#80, #82).
- Plan approval progress, eligible approvers, digest, human rule, and staleness (#78, #83, #59).
- Guarded rollback that asks for the environment name (#67).
- Maintenance windows as a 7-day strip; observed Docker and model runtime (#66, #63).
- Delivery holds and retry of held failed targets (#58).
- Package migrations on Releases; compatibility evidence submission (#64, #65).
- Fleet tables from bulk routes, with an initial-JS budget and fleet-scale load check (#89, #46).

### Changed

- API types are generated from the vendored Tenkai `v0.6.0` contract; CI fails on pin or type drift (#94, #44).
- Signed `v*` tags are verified, then released from `main`. `-rc.N` publishes as a GitHub pre-release. The zip, `SHA256SUMS`, SBOM, provenance attestations, and family manifest attach to the GitHub Release (#93, #96).

### Fixed

- Catalog publish and promote honor the publish capability (#32).
- Release gate flags count only pull requests in the release range (#97).
- CI retries Playwright `--with-deps` when a GitHub runner cannot reach Ubuntu apt mirrors (#150).

## [0.2.0] - 2026-10-07

### Upgrade

Tenkai pins the console in `ui/console.pin`. To serve this release, pin `v0.2.0` with the SHA-256 of `tenkai-console-v0.2.0.zip` from `SHA256SUMS`. It needs a server that serves contract `tenkai.http.v1`, the same contract as v0.1.0.

### Added

- **Subscribe** an environment to a product channel from Environments (#15).
- **Publish, promote, and recall** releases from Releases. Signing stays outside the browser (#16).
- **Reconcile:** request one tick from Delivery and see the server's per-environment report (#17).

### Changed

- Every management action asks for confirmation once, and the confirmation names exactly what will be sent. The server's message is shown as sent, and a lost response reads as unknown rather than success.
- Each click sends one request with its own `x-request-id`, never retried.
- After the server refuses the signed-in credential for an environment or for the fleet, that scope's controls are hidden for the rest of the session.

### Fixed

- A management click made while the browser was offline (approve, apply, plan, rollback, retire) was held and sent on reconnect. It is now refused immediately and shown as unknown.
- README claims about `/ui` serving and same-origin requests (#14).

### Known limits

- Tenkai serves no listing of a caller's grants, so a read-only credential sees management controls until its first refusal.
- There is no release listing route, so a recalled channel head still shows as the head until another release is promoted.
