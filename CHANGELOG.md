## [0.2.0] - 2026-10-07

### Upgrade

Tenkai pins the console in `ui/console.pin`. To serve this release, pin `v0.2.0` with the SHA-256 of `tenkai-console-v0.2.0.zip` from `SHA256SUMS`. It needs a server that serves contract `tenkai.http.v1`, the same contract as v0.1.0.

### Added

- **Subscribe** an environment to a product channel from Environments (#15).
- **Publish, promote, and recall** releases from Releases. Signing stays outside the browser (#16).
- **Reconcile:** request one tick from Delivery and see the server's per-environment report (#17).

### Changed

- Every management action asks for confirmation once, and the confirmation names exactly what will be sent. The server's message is shown as sent, and a lost response reads as unknown rather than success.
- Each click sends one request with its own `x-request-id`, never retried.
- After the server refuses the signed-in credential for an environment or for the fleet, that scope's controls are hidden for the rest of the session.

### Fixed

- A management click made while the browser was offline (approve, apply, plan, rollback, retire) was held and sent on reconnect. It is now refused immediately and shown as unknown.
- README claims about `/ui` serving and same-origin requests (#14).

### Known limits

- Tenkai serves no listing of a caller's grants, so a read-only credential sees management controls until its first refusal.
- There is no release listing route, so a recalled channel head still shows as the head until another release is promoted.
